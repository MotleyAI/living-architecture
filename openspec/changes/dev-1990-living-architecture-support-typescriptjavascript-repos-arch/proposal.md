## Why

The core of this repo is the skills and the formal representations (LikeC4 model, `index.yaml`, arc42 tags,
OpenSpec), yet every `la-*`/`dr-*` command is Python, so a TypeScript-only setup cannot use it without a
Python toolchain. The goal is two native implementations (twins): the PyPI package for Python repos and a new
npm package for TS/JS repos. They are kept identical by sharing their parameters, wording and CLI surface as
data, and by a shared conformance corpus. This change is PR 1 of 4. It lays the foundation in Python only:
the symmetric repo layout, the shared contract, the frozen conformance goldens, and this repo's own
architecture. The npm twin follows in DEV-2025, TS conventions and the typecheck ratchet in DEV-2026, and
TS refactoring, neutral skills and the acceptance run in DEV-2027.

## What Changes

- **Symmetric layout**: the Python package moves to `python/`. The repo root keeps only what both twins share:
  `shared/`, `conformance/`, `plugin/`, `architecture/`, `openspec/`, `AGENTS.md`, `CLAUDE.md`.
- **Shared contract** under `shared/`:
  - JSON Schemas for `living-architecture.yaml` and `index.yaml`
  - the findings registry (message templates)
  - the CLI manifest
  - the conventions and languages registries
  - the review bash scripts

  Each package vendors a byte-copy (a contract snapshot carrying a hash) and loads it at runtime.
  `scripts/sync-shared` refreshes the copies, and a drift test fails when a copy is stale.
- **Conformance corpus** under `conformance/cases/`. Its goldens are generated by the pre-restructure tool
  and frozen before any code moves. Every observable output must stay byte-identical: findings, stdout,
  stderr, exit codes, accepted flags, config semantics and generated diagrams. Explicitly excluded:
  - `--help` text
  - parser error wording
  - the wording of validation errors for invalid config files (the exit code and the offending key stay)
  - internal module paths
- **Python restructure** into node packages that mirror the planned npm twin: `contract`, `config`, `cli`,
  `c4`, `archcheck`, `lang`, `conventions`, `review`, `doctor`, `refactor`. **BREAKING** for in-process
  importers only:
  - `living_architecture.arch_check` → `living_architecture.archcheck`
  - `living_architecture.arch_diagrams` → `living_architecture.c4`
  - `deterministic_refactor` → `living_architecture.refactor`

  The command names are unchanged.
- **CLI built from the manifest** with fixed parser semantics. **BREAKING (minor)**: prefix-abbreviated long
  flags (e.g. `--bas` for `--base`) are no longer accepted.
- **`index.yaml` `source_root`**: an optional source root, defaulting to the repo root, so src-layout
  packages can be checked.
- **`issue_key_pattern`** must use the portable regex subset shared by both twins.
- **This repo's own `architecture/`**: a LikeC4 model of the node decomposition (which is also the import
  law), a view, `index.yaml`, and `system.arc42.md`.
- **`AGENTS.md`** records the twin-sync mechanisms. **`CLAUDE.md`** imports it.

## Capabilities

### New Capabilities
- `shared-contract`:
  - configuration and `index.yaml` parameters, defaults and validation come from shared schemas
  - every user-facing finding and gate text is rendered from the shared registry
  - every command's surface is built from the shared CLI manifest
  - the vendored copies match `shared/`
  - outputs reproduce the conformance goldens
- `arch-check`: the `source_root` setting in `index.yaml`, which separates the source location from the
  repo root.

### Modified Capabilities
(none — the OpenSpec corpus is empty)

## Impact

- Code: everything under `src/` and `tests/` moves and is restructured; the review scripts move to
  `shared/scripts/`.
- Dependencies: adds `jsonschema` to the Python package.
- Packaging and CI: the Python project lives in `python/` (with vendored `README.md` and `LICENSE`). CI and
  the publish workflow run there. CI builds the wheel and sdist and smoke-tests them outside the checkout.
- Skills: `test_skills` takes its command set from the CLI manifest. Skill text is unchanged in this PR.
- Users: same commands and outputs. `uv tool install -e <checkout>/python` for editable installs.
